Resumen Ejecutivo: Este documento consolida la arquitectura de despliegue más segura, moderna y económica para la plataforma ATLAS Gym. Descartando configuraciones manuales obsoletas (como abrir puertos en cortafuegos o renovar certificados SSL en Linux a mano), se adopta el estándar Cloudflare Tunnel (Zero Trust). El servidor VPS de Hostinger corre los contenedores Docker de forma aislada, manteniendo cerrados todos los puertos de entrada, mientras Cloudflare administra el dominio, provee HTTPS automático y absorbe cualquier intento de ataque DDoS.

2. Titularidad de Cuentas y Gestión Profesional de Accesos

Por seguridad jurídica, contable y técnica, las cuentas maestras deben pertenecer al cliente (dueño del gimnasio). La gestión técnica se delega al equipo de desarrollo mediante mecanismos oficiales sin compartir claves personales:

Plataforma Titularidad (Cliente) Mecanismo de Acceso Técnico (Desarrollador)
Hostinger (VPS) Cuenta creada con email institucional del gym y tarjeta del cliente para el débito automático. El cliente usa la función "Compartir cuenta" (Account Sharing) invitando al email del programador. El desarrollador administra el servidor sin ver datos de tarjetas ni facturación.
Cloudflare Cuenta gratuita registrada con el correo del gimnasio donde se vincula el dominio adquirido. El cliente añade al desarrollador en Manage Account ➔ Members con rol de Administrator. Permite configurar DNS, túneles y reglas de seguridad sin intermediarios.
GitHub Repositorio de la organización o del desarrollador con control de versiones. Se generan Deploy Keys (llaves SSH de solo lectura) en el VPS de Hostinger para permitir la descarga segura del código fuente sin exponer contraseñas.

3. Registro de Dominio y DNS con Cloudflare

A. Selección y Registro

  • Dominio Internacional (.com): Se recomienda registrarlo directamente en Cloudflare Registrar (~$10 USD/año al costo mayorista sin recargos) o en proveedores reconocidos como Namecheap.
  • Dominio Nacional (.com.ar): Se gestiona ante NIC Argentina en moneda local. Una vez otorgado, se cambian los DNS primarios apuntando a los *Nameservers* asignados por Cloudflare.

B. Estructura de Subdominios Recomendada

  • atlasgym.com o app.atlasgym.com: Destinado a la interfaz visual de Next.js (Portal del alumno, panel administrativo y tótem).
  • api.atlasgym.com: Destinado a la API REST de Spring Boot (Endpoints de autenticación, cuotas y rutinas).

4. La Solución Moderna: Cloudflare Tunnel (Zero-Trust)

Históricamente, para publicar una web en un VPS se requería abrir los puertos 80 y 443 en el router/firewall, configurar Nginx en Linux y pelear con la renovación periódica de certificados Let's Encrypt. Cloudflare Tunnel reemplaza por completo ese esquema obsoleto.

¿Cómo funciona Cloudflare Tunnel?
Se instala un agente ligero en el VPS llamado cloudflared. Este agente establece una conexión saliente TLS segura con el centro de datos más cercano de Cloudflare. El tráfico de los alumnos entra por Cloudflare y baja por ese túnel privado directo a los contenedores locales.

Ventajas del enfoque moderno:

  1. Cero puertos de entrada abiertos en el VPS: El cortafuegos de Hostinger puede tener cerrados el puerto 80, 443 y 3306. Los escaneos de puertos de hackers rebotan por completo.
  2. IP de Hostinger 100% anónima: Nadie en internet puede descubrir cuál es la dirección IP real de tu servidor.
  3. Certificados SSL transparentes: Cloudflare emite y renueva el candado HTTPS en sus servidores de borde sin necesidad de configurar nada en Linux.
  4. Configuración visual desde el navegador: Los subdominios se asocian en el panel de Cloudflare Zero Trust indicando simplemente:
    • Dominio atlasgym.com ➔ Servicio http://localhost:3000
    • Dominio api.atlasgym.com ➔ Servicio http://localhost:8080

5. Arquitectura de Contenedores Docker en el Servidor

En el VPS de Hostinger se levanta la solución completa mediante Docker Compose. Los tres servicios conviven en una red interna cifrada donde MySQL nunca se expone a internet:

Servicio Técnica Docker Seguridad Persistencia
Backend (Spring Boot) Multi-stage: compila con Maven JDK 17 y corre sobre JRE 17 Alpine (~180 MB). Usuario sin privilegios (atlasuser), no-root. Estateless (sin estado en disco).
Frontend (Next.js 16) Build optimizado standalone sobre Node 20 Alpine (~100 MB). Usuario sin privilegios (nextjs), no-root. Estateless (cacheado en memoria).
Base de Datos (MySQL 8) Imagen oficial con charset UTF8MB4 y credenciales inyectadas por entorno. Aislado en red interna. Puerto 3306 no mapeado al host. Volumen persistente montado en disco host (mysql_data).

6. Ciclo de Vida de Actualizaciones en Producción

El mantenimiento diario y subida de nuevas características se realiza sin fricción en cuestión de segundos:

1. DESARROLLO (Tu PC): git add . && git commit -m "feat: nueva mejora" && git push origin main 2. VPS DE HOSTINGER: ssh root@ip-del-vps cd atlasgym git pull docker compose up -d --build
Recompilación inteligente: Gracias al sistema de capas de Docker, al ejecutar docker compose up -d --build, Docker solo recompila los archivos modificados. El tiempo de bajada y actualización toma menos de 45 segundos y la base de datos MySQL no se reinicia ni pierde datos.
